# LE Turbo v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Rust + Tauri desktop app that presses a configurable list of keys and mouse buttons on repeating intervals inside Last Epoch, with a safe focus gate and no way to leave an input stuck.

**Architecture:** Pure logic (key parsing, profile model, scheduling, safety predicates, held-input bookkeeping) lives in small modules with unit tests and no Win32 dependency. Every Win32 touch (SendInput, foreground window, cursor, monitors, screen capture, hotkey polling) sits behind a one-method trait, so the engine loop is tested entirely against fakes with an injected clock. A Tauri command layer exposes state to a static, framework-free HTML/JS frontend. All of this is one binary.

**Tech Stack:** Rust (edition 2021), Tauri 2, `windows` crate 0.58+ for Win32, `serde`/`serde_json` for profiles, `tauri-cli` 2. No npm, no bundler: `ui/` is static HTML/CSS/JS and Tauri serves it directly with `withGlobalTauri` enabled.

**Spec:** `docs/superpowers/specs/2026-10-12-last-epoch-turbo-design.md`

**Out of scope:** v2 (buff detection by pixels). This plan builds v1 only. The
profile schema already reserves the v2 `Condition` field (Task 3) so shipping v2
later does not invalidate v1 files.

## Global Constraints

- Windows x64 only. Never requires administrator rights at runtime.
- Input goes through `SendInput` only. No process memory access, no injection, no kernel driver, no hooks.
- Minimum interval is **10 ms** (`MIN_MS = 10`). Any smaller value clamps to 10.
- Rows default to **disabled**. Arming is always an explicit user action.
- Mouse-button rows are skipped unless the cursor is inside the game window (always, independent of the focus gate).
- Hotkeys are fixed **F2** (arm), **F3** (disarm), **F9** (quit) in v1, stored in app config, not the profile.
- The focus gate matches the foreground window's **process image name**, default `Last Epoch.exe`, stored in app config.
- A held input must never outlive the app: `release_all` runs on disarm, quit, focus loss, and panic.
- All user-facing UI text is **English**, and lives only in `ui/strings.js`.
- Profile and app config are two separate JSON files next to the executable.
- Profile schema version starts at `1` and must be forward-tolerant: unknown fields are ignored on load, and v2 condition fields are already reserved.
- Commits are local only. Pushing is `/commit-push`'s job, not this plan's.

## Review Focus

The spec is a vision document; these are the input classes and failure modes it implies that no single task proves on its own. Each one gets a test in the task that owns the code, named here so it is not lost.

1. **A held mouse button surviving disarm, focus loss, quit or panic** — a stuck left button drags/selects on the user's desktop and is the worst outcome this app can produce. Owner: Task 7.
2. **A mouse row firing while the cursor is over another window** — measured as possible (the game does not clip the cursor). Owner: Task 7.
3. **Injecting while a non-game window is focused** — e.g. the user alt-tabbed to a chat client. Owner: Task 7.
4. **A profile file from a newer or older version, or with unknown fields, causing a crash or data loss on load.** Owner: Task 3.
5. **An interval below the floor, or a zero/negative value, producing a runaway loop.** Owner: Task 5 (scheduler) and Task 3 (normalize).
6. **An unknown/garbage key name in a row panicking or silently injecting the wrong key.** Owner: Tasks 2 and 7.

### Task 5: Press scheduler

**Files:**
- Create: `src/schedule.rs`
- Modify: `src/lib.rs` (add `pub mod schedule;`)
- Test: `src/schedule.rs` (inline `#[cfg(test)]`)

**Interfaces:**
- Consumes: `crate::profile::{Row, RowAction}`, `crate::profile::MIN_MS`.
- Produces:
  - `pub struct RowClock { pub last_fire_ms: Option<u64> }`

  - `pub fn due_rows(rows: &[Row], clocks: &[RowClock], now_ms: u64) -> Vec<usize>`

`due_rows` returns the indices of rows whose action is `Press`, whose `enabled` is
true, and whose elapsed time since `last_fire_ms` is at least `ms.max(MIN_MS)`.
A row that has never fired is due immediately. `clocks` is parallel to `rows`; a
missing entry is treated as never-fired. `Hold` rows are never returned.

  - `pub fn Engine::arm(&mut self)` / `pub fn Engine::disarm(&mut self)`

  - `pub fn Engine::set_gate(&mut self, gate: bool)`

  - `pub fn Engine::tick<P: GameProbe>(&mut self, probe: &P, now_ms: u64)`

  - `pub fn Engine::presses(&self) -> u64` / `pub fn Engine::skipped(&self) -> u64` / `pub fn Engine::is_armed(&self) -> bool`

`tick` is the whole behaviour:

1. Store `now_ms`.
2. Compute `game_ok`: if `gate` is true, `focus_matches(&expected_process, probe.foreground_process())`, else `true`.
3. **Watchdog:** if `hold_armed` and `!game_ok`, call `sink.release_all()`, set `hold_armed = false`.
4. If `!armed || !game_ok`, return.
5. If `!hold_armed`: for every enabled row whose action is `Hold`, `sink.hold(key)` when the key parses; count failures into `skipped`. Then set `hold_armed = true`.
6. For each index from `due_rows(&rows, &clocks, now_ms)`: parse the row key; if parsing fails, `skipped += 1` and continue; if the key is a mouse key and `probe.cursor_pos()` is not inside `probe.game_window_rect()`, `skipped += 1` and continue; otherwise `sink.press(key)`, and on success set `clocks[i].last_fire_ms = Some(now_ms)` and `presses += 1`.

`disarm` calls `sink.release_all()` and clears `hold_armed`.

`Engine::new` sets `gate = true` — the spec requires the focus gate to be on by
default, and a fresh install must not inject into whatever window is in front.

`set_rows` also rebuilds `clocks` (one `RowClock { last_fire_ms: None }` per row)
so newly added rows fire on the next tick.

### Task 11: Global hotkeys by polling

**Files:**
- Create: `src/win/hotkeys.rs`
- Modify: `src/win/mod.rs`, `src/lib.rs` (`run()` starts the poller)
- Test: `src/win/hotkeys.rs` (inline, for the edge detector)

**Interfaces:**
- Consumes: `crate::state::AppState`.
- Produces:
  - `pub enum Hotkey { Arm, Disarm, Quit }`

  - `pub const HOTKEYS: &[(Hotkey, &str, u16)]` = `[(Arm, "F2", 0x71), (Disarm, "F3", 0x72), (Quit, "F9", 0x78)]`

  - `pub struct EdgeDetector { down: [bool; 3] }`

  - `pub fn EdgeDetector::poll(&mut self, states: [u16; 3]) -> Vec<Hotkey>`

  - `pub fn spawn_hotkey_loop(state: AppState, stop: Arc<AtomicBool>) -> JoinHandle<()>`

`EdgeDetector::poll` takes one `GetAsyncKeyState` result per hotkey and returns
the ones that are newly pressed. A key counts as newly pressed when its high bit
(`0x8000`, currently held) is set and it was not held on the previous poll, **or**
when its low bit (`0x0001`, pressed-since-last-poll) is set. The low bit is what
catches a tap shorter than the poll interval.

- [ ] **Step 1: Write the failing tests**

        let mut d = EdgeDetector::new();
        assert_eq!(d.poll([UP, UP, UP]).len(), 0);
        assert_eq!(d.poll([DOWN, UP, UP]), vec![Hotkey::Arm]);
        assert_eq!(d.poll([DOWN, UP, UP]), vec![], "still held must not refire");
        assert_eq!(d.poll([UP, UP, UP]).len(), 0);
        assert_eq!(d.poll([DOWN, UP, UP]), vec![Hotkey::Arm]);
    }

    }
